# 렌더링 최적화 검증 (2026-10-16)

요청 범위: 휴대폰 설치 앱의 발열을 계기로, 기본 화질을 낮추지 않고 불필요한 처리를 줄인다. 프레임 상한은 60FPS.

## 반영

- 60FPS 상한. 30/60/90/120/144/165/240Hz 콜백을 모사해 60Hz 화면이 30FPS로 떨어지지 않는지 검사했다. 백그라운드에서는 애니메이션 루프를 중단하고 복귀 시 타이머·입력을 초기화한다.
- 복셀 지형에서 같은 크기의 이웃 기둥이 완전히 덮는 옆면을 제거한다. 밑면, 윗면, 크기가 다른 격자 경계는 보존한다. 최대 16가지 면 조합을 인스턴싱한다.
- 자리 표시판 72개를 하나의 InstancedMesh로 묶는다. 거치 상태가 바뀔 때만 색 버퍼를 갱신한다.
- 복셀 장면에서 플레이어 위치와 그림자를 드리우는 동적 물체가 모두 정지·부재 상태이면 그림자 맵을 재사용한다. 낚싯대·다른 플레이어·고기·끌어내기·손에 든 고기가 있으면 매 프레임 갱신한다. 동적 물체가 사라진 다음 한 번 더 갱신한다. 다른 그래픽 스타일은 계속 갱신한다.
- 활성 물보라가 없으면 입자 계산·버퍼 업로드·그리기를 생략한다. 수면 셰이더에는 수명 내의 파문만 전달한다.
- 전체 조과를 검사하는 보상 알림 계산은 초당 4회로 줄인다. 장력·캐스팅 표시와 입력 갱신은 60FPS 상한 내에서 계속 동작한다.

해상도, MSAA, 그림자 해상도, 반사 해상도·갱신 빈도는 변경하지 않았다.

## 검증 결과

원본과 최종 복셀 인스턴스 240,546개의 변환·색·셰이더 속성을 정렬해 비교했다. SHA-256이 모두 `a090d1b8869b5ad0dc8a72e92d4076efe76f0d06549fb880b09a6d5c248e8e4d`로 같았다. 제거한 것은 가려진 옆면의 인덱스다.

기본 맵의 지형·나무만 계산하면 GPU에 제출하는 삼각형은 2,886,552개에서 2,179,966개로 24.5% 감소했다. 지형·나무 그리기 호출은 2회에서 17회로 증가하지만, 자리 표시판 배치가 장면 전체의 호출을 크게 줄인다.

로컬 Chrome의 960×540 합성 장면(지형·나무·좌대·하늘·수면 반사·그림자, 후처리와 실제 낚시 플레이 제외)에서 원본과 최종 장면을 번갈아 그렸다. GPU 시간은 EXT_disjoint_timer_query_webgl2를 사용했다.

| 항목 | 원본 | 최종 |
|---|---:|---:|
| CPU 렌더 제출 시간, 교차 측정 평균 | 3.30ms | 1.33ms |
| GPU 시간, 교차 측정 평균 | 6.93ms | 6.43ms |
| 프레임 전체 그리기 호출, 반사·그림자 포함 | 187 | 70 |
| 프레임 전체 제출 삼각형 | 6,099,246 | 4,686,866 |

이 수치는 PC의 짧은 합성 측정이며, 휴대폰 FPS·발열·전력 개선율로 일반화하지 않는다. 픽셀 비교는 518,400픽셀 중 532픽셀이 달라 완전 일치는 아니다. 메시 배치 변경에 따른 경계·그림자 차이까지 포함하므로 모든 시점에서 시각적 동일성을 증명한 결과는 아니다.

공간 청크로 세분화하는 안은 삼각형 수는 줄었지만 호출 수가 늘어 실측 이점이 확인되지 않아 제거했다. 지형 밑면 제거도 반사 화면의 차이를 늘려 제외했다.

`npm run test:render`: 프레임 제한, 물보라 활성/수명/순환 풀, 파문 수명/순환 풀, 표시판 색 갱신, 배치 경계, 제출량 검사.

`npm run build`, `npm run test:render`, `git diff --check`는 최종 상태에서 통과했다. 실제 휴대폰의 장시간 플레이·온도 측정과 운영 배포는 별도다. 현재 Android 앱은 Manifest의 `DEFAULT_URL`로 Hosting 게임을 여는 TWA 구성이다.
